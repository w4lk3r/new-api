## 视频验证分层

1. 在未合并私有代码的官方基线上运行插件运行时、控制器、路由、任务服务、模型和 relay 测试。

官方基线测试命令：


该命令已在官方 `rc.31` 原始基线上通过。它不能替代具体 Dola 插件的 HTTP 集成测试和真实上游验收。

### 已确认的创建阻断

收到的原始插件在官方运行时中的 9 条 fixture 全部通过，但真正经过 TokenAuth、渠道分发、预扣费和 HTTP 发送的创建请求失败：模拟上游收到 multipart 请求体，却没有对应的 `Content-Type: multipart/form-data; boundary=...`，因此返回 400。

`relay/channel/task/jsplugin/adaptor.go` 构造 multipart 时把 Content-Type 写入入站 Gin request；通用发送函数另建了 HTTP request，而插件适配器的请求头构建没有将该 Content-Type 复制过去。原始插件不应自行猜测由宿主生成的 boundary。

JSON 输入也未通过：插件描述的是发往上游的 multipart 请求，但宿主无条件把入站 JSON 当成 multipart 解析，尚未请求上游便返回 HTTP 500（`multipart boundary not found`）。因此仅改客户端提交格式不能绕过两个阻断。

本阶段不修补官方生产转发代码，也不修改收到的插件来隐藏此问题。保留明确启用的创建复现测试；默认跳过此已知失败的探针，不将错误的 400 固化为正确协议。通过种入测试 Task 验证的查询、下载、归属与退款，只证明这些下游环节可用，不能被描述成创建到完成的全链路通过。

创建探针配置每任务 USD 0.25、分组倍率 2，验证失败后的用户钱包与 Token 配额均恢复到预扣前数值。此处只有临时数据库里的模拟额度，没有真实上游扣款。样本 SHA-256、测试命令与协议限制见 [插件测试说明](../controller/testdata/custom-video/README.md)。

因此暂不迁移私有视频三个提交。后续应先单独修复并回归该宿主缺陷，或验证已修复的官方版本，再做真实上游联调和历史视频数据迁移。

## 升级前必须处理的数据与行为

- 私有 `NativeVideo = 59` 与官方 `Sub2API = 59` 冲突；官方 `TaskPlugin = 61`。本分支不能直接连接含私有 59 渠道的生产库。
- 历史 Lingjing Task 的 `platform = lingjing` 或旧 `59`、私有渠道 `adapter_key`，需要与官方插件键、私有任务数据和计费快照一起设计迁移；仅修改渠道数字不够。
- 官方视频计费体系变化，旧视频价格不能直接假设继续有效。Dola 插件没有时长用量声明；发送 `seconds=30` 不等于宿主自动按秒收费。
- 官方插件可提供原生路由和模型入口，但我们原有的默认模型、分组覆盖、跨平台能力筛选不能视为已自动迁移。
- 原生接口/公共任务 ID 的历史兼容、上传资源归属、上游幂等键范围、视频结果 URL 的有效期需要单独验收。
- 官方升级并不代表此前审查的任务内核风险已经全部消失：`rc.31` 轮询仍存在按平台内上游 ID 建索引的代码，失败终态与资金退款也不是一个数据库事务。跨渠道重复 ID 和退款中断恢复仍须单独回归，不因常规插件测试通过而忽略。

## 数据库验收

所有外部数据库测试只能使用专用的可丢弃测试库，禁止设置成业务库。工作流 `.github/workflows/fork-database-tests.yml` 提供 MySQL 8.0 和 PostgreSQL 16 服务；SQLite 使用测试创建的临时库。

```sh
TEST_MYSQL_DSN='专用 MySQL 测试库 DSN' \
TEST_POSTGRES_DSN='专用 PostgreSQL 测试库 DSN' \
go test -count=1 -v ./model
```

验收必须覆盖新库、历史表升级、连续两次迁移、流水及余额保留和唯一约束。没有对应数据库的实际执行结果时，不宣称数据库兼容性验证完成。代码合并和生产部署是两个独立阶段；部署前仍需生产库备份、恢复演练和历史视频迁移方案。
